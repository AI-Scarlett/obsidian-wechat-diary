# 「切换文件夹」草案 v1 审稿汇总

三视角审稿 → 三驳斥者复核后存活 21 条, 合并重复后 15 个问题 + 1 组含糊点。分三组: A 草案直接改(11)、B 需要谷雨拍板(4)、C 记录在案不改(5)。组内按严重度排序。

## A. 草案直接改(有明确更优解, 不需要谷雨决定)

### A1. 「撤回」按 last_write 定位必须限定在同一逻辑日, 翻页时清空 last_write
合并: MEMO-1 + MULTI-3(①②) + ENG-3。涉及 §3 `last_write`、§5.2「任意 | 撤回」行及「撤回后 last_write 不清」、§5.3。
问题: 现状 `undoLastBlock()`(main.js 3385)不传日期只碰今天的文件, 今天没文件回 UNDO_EMPTY_REPLY, 昨天一个字不动。草案让撤回改按 `session.last_write` 定位, 但 §3 没给 last_write 任何有效期, §5.3 翻页只清 `session.folder` 不清 last_write。结果: 不配规则的备忘录用户昨晚「血压 130/85」+「晚安」封存, 今早第一条发「撤回」(语音误转等) → 删的是昨天已封存文件的最后一条, 回执 `undoOkReply` 不带日期, 用户看不出。这直接违反 §4 末尾「没配规则时一切与 0.3.1 完全相同」, 且删的是已封存历史, 不可逆。
改成: ①`_loadOrReset` 的 `entered_date !== today` 分支里, 清 `s.folder` 的同一处顺手 `s.last_write = null`; ②UNDO 分支只在 `last_write && last_write.date === logicalTodayStr()` 时按它定位, 否则回落到「当前分区的今天文件」(空则 UNDO_EMPTY_REPLY); ③§5.2 撤回行补一句「last_write.date 不是今天 → 撤当前分区的今天文件」。这样 folderRules 为空时 last_write 永远等价于「今天的默认日记」, §4 的承诺才成立, §2.4「撤全局最后一条」的"全局"自然限定在逻辑日内, 不碰拍板。
记账入口: last_write 的更新只放 `_noteWrite` 一个出口(它是 3856/3872/3904/3925/3949/3969 六个写入路径的唯一公共出口, 文字/语音原声/图片/文件/视频/语音兜底都走它)。注意生产路径上 `_writeEntry`/`_writeAllMedia` 都不传 dateStr, 六个写入点的 dateStr 永远是 undefined——建议让 DiaryWriter 的每个写入方法在返回值里带上它实际用的 `{day, folder}`(内部本来就算了 `day = dateStr || logicalTodayStr()`), `_noteWrite(res)` 从结果取, 一处改完六处生效。
测试: bindtest 加「无规则 + 翻页 + 撤回 → UNDO_EMPTY_REPLY」「翻页后 last_write 已清」两条断言。
(去掉 MEMO-1 原建议里「folder 仍在规则里」这个条件: last_write 存的是路径, 规则删了文件还在, 最后一条确实写在那, 撤那里才对; 规则删除只影响 §5.7 的下一条写入去向。)

### A2. 「切换词 + 内容」导致切换的那条回执要带退出提示
MEMO-2(①部分)。涉及 §5.2 第 2 行「日记 | 切换词 X + 内容」、§6「分区写入」。
问题: §5.2 第 1 行(单独切换)回执有「(说「回来」回日记)」, 第 2 行(切换词+内容)只有「记下来啦~ 「梦游太虚幻境」第 1 段」, 没有任何退出线索; 而 §5.2 又规定分区里不挂开页 tips, 之后每条都不会再提怎么回来。§1 自己定义「入梦 昨晚飞了」是主形态, 误触也几乎总是带内容的形态(语音转写「梦，……」同样触发)。误触的人接下来会试「退出」「返回」「回日记」, 全被当内容记进分区, 越急越错。保险①(回执带文件夹名)和保险③(「结束」)能保证不真困死, 但自救成本高。
改成: 凡本条消息导致 `session.folder` 发生变化的写入回执, 末尾挂一次退出提示, 与单独切换那行同一句, 沿用「一条回执一个括号」规则, 例如「记下来啦~ 「梦游太虚幻境」第 1 段 (切到这里了, 说「回来」回日记)」; 之后各条维持短回执, 不啰嗦。回执模板多一个变量, 零成本。

### A3. 跨天「已回到日记」的告知与「是否真自动封存」解耦; 封存集合要包含 session.folder; 首条即切换时不说「已回到日记」
合并: MEMO-6 + MULTI-3(③) + ENG-2。涉及 §5.3、§5.7。
问题: 现有 `_loadOrReset`(3825–3836)只在 `finalizeDay` 返回 `sealed` 时才给 GRACE_EXPIRED_NOTICE(D9 定的「只有真自动封的才说自动收尾」)。草案 §5.3 把「已回到日记」硬绑在这句文案上, 于是: 昨晚说了「晚安」(全封)后又「入梦 又梦到了」补一条再睡 → 翻页时梦境和日记都是 `already`, 没有任何括号, 但 `session.folder` 已被清空; 早上直接接着说梦, 落进日记, 回执只有「今天第 1 段」没有文件夹名——这正是骨架②要防的静默错位。三个附带问题: ①§5.3 封存循环只跑「默认 + 每条规则的文件夹」, 而 §5.7 允许 `session.folder` 指向已删规则的路径, 那个文件夹昨天的文件永远封不上; ②跨天后第一条就是「入梦 xx」时, 按 `_dispatch`(4148)的拼接顺序, 回执会是「(昨天的已自动收尾, 已回到日记)」紧接「记下来啦~ 「梦游太虚幻境」第 1 段」, 前后矛盾; ③`willNotice`(4144)只认一种告知, 新告知会与夜间提示同条出现两个括号。
改成: `_loadOrReset` 返回 `{ sealedAny, wasInFolder }` 两个信号, 文案两句独立拼——「昨天的已自动收尾」只在 sealedAny 时说(与 D9 一致); 「已回到日记」只要翻页前 `session.folder !== ""` 就说, 与封没封无关。组合: 两者都有 → 「(昨天的已自动收尾, 已回到日记)」; 只 wasInFolder → 「(新的一天, 已回到日记)」; 只 sealedAny → 现有句; 都没有 → 不告知。告知在 `_dispatch` 末尾按「本轮结束时 session.folder 是否仍为空」决定: 本轮又切换了 → 只保留 sealedAny 对应的现有告知或不告知(切换回执自带文件夹名已说明位置)。封存循环的集合 = 默认 + 规则文件夹 + session.folder(去重), 抽成 `_allFolders()` 给「晚安」复用。`willNotice` 改为「任一告知存在」。挂载位置沿用 `cross.expiredNotice`, 一条回执仍只一个括号。

### A4. 「晚安」封多文件的三态聚合、部分失败、「在默认日记里说晚安」都要定义
合并: MULTI-5 + ENG-4。涉及 §2.2、§5.4、§5.2「晚安」行。
问题: `signoffReply(det, r)`(2647)只吃一个 finalizeDay 结果(sealed / already+afterSeal / 其余只道别 / error), `_handle` FINALIZE 分支(4044–4056)的 `finalize_count`/`reminded_date` 记账也按单结果 `status !== "error"` 判。草案 §5.4 只定义了 n 求和, 没定义多个 status 怎么折成一个: 只记了 5 条梦、默认日记空 → 若沿用默认日记的 r(empty)就回「晚安, 明天见」, 5 段梦既不报数也不知道封没封; 默认封成功、梦境 finalizeDay 抛错 → 回 FINALIZE_FAIL_REPLY「收尾标记没写上」与事实不符(默认明明写上了), 重发「晚安」又变 already。另外 §5.2 表只有「X | 晚安」一行, 谷雨自己的日常流程是早上记梦、「回来」、晚上在默认日记里说「晚安」——如果实现者只在分区里才封所有文件, 梦境要等凌晨 4 点自动封, 第二天被告知「昨天的已自动收尾」, 正是 D9 修掉的那种错告知。
改成: 新增 `finalizeAll(day, folders)` 返回聚合结果: `n = Σn`; `status`: 任一 sealed → sealed; 否则任一 afterSeal>0 → already(afterSeal=Σ); 否则全 empty → empty; 全部 error → error; 部分 error → 按成功部分出文案, 尾部加一句「(「X」的收尾标记没写上)」(失败必须响亮, 但要准确)。`finalize_count`/`reminded_date` 在「不是全 error」时记(沿用 D9「说过收尾词就计数」)。明细括号只在 ≥2 个文件有内容时出现, 只有默认有内容时文案与现状逐字一致。§5.2 补一行「日记 | 晚安 | 封今天所有有内容的文件(含分区), 不切换」, 注明是 §2.2 的落实不是新决策。`finalizeAll` 接受文件夹列表参数: 「结束」传 `[session.folder]`(2.3 只封当前分区), 「晚安」传 `_allFolders()`, `_loadOrReset` 跨天封存也复用它(sealedAny = 任一 sealed)。bindtest 加「仅分区有内容 + 晚安」「默认已封 + 分区未封 + 晚安」「部分 error」三例。

### A5. 关键词校验改用 detectIntent 判, 前置应答词必须拒, 删掉 §5.1 第 4 条的错误建议
合并: MEMO-7 + MULTI-9 + ENG-6。涉及 §4 校验、§5.1 第 4 条。
问题一(校验漏): §4 说「按 normalizeIntent 后与 7 张词表比」, 但 `detectIntent`(2792–2842)命中命令的路径远多于查表——`intentForms` 的「啦→了」补形态(2780)、`foldRepeats` 复读折叠、`isUndoPhrase` 尾巴白名单、`tokenizeClosing` 多段告别、`START_DIARY_PHRASES` 的 includes。实测 `normalizeIntent("记完啦")` = 「记完」不在任何表里, 校验放行, 但 `detectIntent("记完啦")` = FINALIZE; 「撤回撤回」「结束晚安」同理。而 §5.2 让切换匹配跑在 detectIntent 之前, 放过的词从此永久遮蔽那条命令。
问题二(§5.1.4 是错的且打穿 D9): 草案说「想剥壳的用户把「好」也配成关键词即可」——配成切换关键词后「好，入梦」= head「好」命中 → 切到「好」所配的文件夹 + 把「入梦」当内容记进去, 根本不是剥壳。更要紧的是 `LEAD_ACK_RE`(2724)里的 好/嗯/那/行/ok 正是 D9 第 1 条「认人话」的核心, 有人真配了, 「好，结束」「嗯 撤回」「好的好的晚安」全部变成切换 + 把命令词记成内容。三个驳斥者对 MEMO-7 曾说「保留 §5.1.4 就不能拒应答词, 二选一」, MULTI-9/ENG-6 的复核给出了答案: §5.1.4 那句本身不成立, 删。
改成: `validateFolderRules` 校验三连: ①`detectIntent(kw).intent !== INTENT.DIARY || d.forced` → 拒(文案沿用「和内置命令重复, 换一个」, 与词表演进自动同步, 顺带覆盖「开始」「早」「测试」等 START/CHAT 单字); ②`LEAD_ACK_RE` 全匹配(m[0].length === kw.length)→ 拒, 文案「「好」是应答词, 换一个」——注意 `detectIntent("好")` 返回 DIARY, 所以这条不能省; ③`stripNoise(kw) !== kw` → 拒(含标点/引号/emoji); 「记」单独拒的规则保留; TAIL_PARTICLES 单字拒。§5.1 第 4 条改为「不剥前置应答词; 前置应答词不能配成关键词(设置页会拒)」。head 与关键词存与比都 `toLowerCase()`(normalizeIntent 已 lower, 2769; 否则英文关键词「OK」/「ok」行为不一致——草案没说)。

### A6. 设置页规则列表不能每键 onChange 即落盘; DEFAULT_SETTINGS 里的数组会跨实例共享
ENG-7。涉及 §4「校验(改完即校, 不合法不落盘; 半截输入不生效)」、§7 DEFAULT_SETTINGS。
问题: 现有设置页「日记文件夹」(4463)和提醒时间(4497)都是每键 onChange 即写。草案 §4 的「半截输入不生效」只覆盖了「字段缺失」, 没覆盖「字段填了一半」: 打「感悟」到「感」时已经是一条完整合法规则(1 字、有文件夹)→ 落盘生效, 实时改路由; 在第二行打「梦境」到「梦」撞第一行的「梦」就弹 Notice, 用户还没打完。代码级: `DEFAULT_DATA`(4578)用 `Object.assign({}, DEFAULT_SETTINGS)` 浅拷贝, onload(4602)再 `Object.assign(base.settings, stored.settings)`——老 data.json 没这字段时 `settings.folderRules` 就是 `DEFAULT_SETTINGS.folderRules` 那个数组本体, push 一条规则等于改了模块常量; bindtest 的 `newPlugin`(78–84)反复建插件, 规则必然跨用例串。
改成: 规则列表用 draft 副本(display() 时从 settings 复制), 校验在 blur/Enter 时跑, 通过的才整体写回 `settings.folderRules`(只含完整规则, 用赋值不用 push); 正在编辑的行不参与匹配; 校验不合法时不回退输入框、只不落盘(别抄提醒时间那支「越界回退」, 否则「梦境」输不进去)。`DEFAULT_DATA` 改成 `Object.assign({}, DEFAULT_SETTINGS, { folderRules: [], exitKeywords: ["回来"] })` 保证每次新建数组; onload 后对 folderRules/exitKeywords 做形状清洗(非数组丢、非字符串项丢、超长截——用户会手改 data.json)。

### A7. 「日记文件夹」改动可以绕过「不等于默认」校验; 路径比较要先归一化; 写明嵌套允许
ENG-8。涉及 §4 校验「文件夹: 不等于默认日记文件夹」、§3。
问题: 校验只在规则侧跑。「日记文件夹」onChange(4463)与 selectSuggestion(4482–4485)无任何校验, 先配「感悟 → 玄学感悟」再把默认改成「玄学感悟」, 默认与分区指向同一文件: 「在吗」「晚安」把同一文件数两遍。`diaryPath`(3179)用 normalizePath 取根, 校验若比原始字符串, 「梦境/」与「梦境」判为不同、实际同一目录(bindtest 的 normalizePath 桩是恒等, 测试发现不了)。
改成: 抽纯函数 `sameRoot(a, b)`(normalizePath + 去尾斜杠 + 空串视为「日记」, 与 diaryPath 兜底一致), 三处复用: 规则校验; 「日记文件夹」onChange/selectSuggestion 撞规则文件夹时 Notice + 回退(与提醒时间做法一样); 运行时 `matchFolderSwitch` 前过滤掉 `sameRoot(rule.folder, 默认)` 的规则(手改 data.json 也挡得住)。§4 顺手写明「分区可以放在日记文件夹里面或外面, 都不串」——已核过 diaryPath/attachmentPath/countMessages, 各根下 YYYY/ 与 attachments/ 都是各自子树。

### A8. 配了规则后, 默认日记里的「在吗」要正面报位置; 并列多个文件夹时用 settings.diaryFolder 的实际名字
MULTI-10。涉及 §5.2「X | 在吗」行、§6「在吗(分区)」、§5.4 明细。
问题: 骨架 §1 写的是「「在吗」报当前在哪」, 草案只定义了分区里那行, 默认日记里仍走 `pingReply`(2580)「在的~ 今天已记 N 段」, 位置只能靠「没出现文件夹名」反推——跨天自动回默认(§5.3)、规则被删回默认(§5.7)之后, 用户最想确认位置时恰好没有正面回答, 这是骨架没落实的缺口。另外 §5.4 明细写死「日记 3 段」: 朋友的默认文件夹叫「生活」, 「(日记 3 段、工作 2 段)」对不上她看到的文件夹名。
改成: `folderRules` 非空时默认日记的探活回「在的~ 现在在「{diaryFolder}」, 今天已记 N 段」(N=0: 「在的~ 现在在「{diaryFolder}」, 想记什么直接发」); 没配规则维持原句(现有测试不动)。凡是把多个文件夹并列的地方(「在吗」「晚安」明细、§5.4)用 `settings.diaryFolder` 的实际名字; 单独出现的「回到日记了」这类泛称维持不变(welcomeText 也这么用, 口径一致; 默认值就是「日记」, 谷雨自己看不出差别)。

### A9. 分区里撤空的回执不能说「今天还什么都没说呢」
MULTI-4(回执部分, 与 B3 拆开)。涉及 §5.2「任意 | 撤回」行、§6。
问题: `undoLastBlock` 返回 ok:false 时 `_handle` 回 UNDO_EMPTY_REPLY「今天还什么都没说呢, 没东西可撤哦」(2596), 在分区里撤空时这句是假话——用户今天在日记里说了很多, 只是这个文件夹撤空了。
改成: 撤空回执按 `session.folder` 分: 分区里「「{folder}」今天还没记东西, 没东西可撤」; 默认日记维持原句。

### A10. 帮助文案: 规则行插进【命令】块, 补齐「结束也能回」「记：」「撤回撤最近写的那个文件夹」
MEMO-9。涉及 §5.2「X | 帮助」行、「写进帮助不写进回执」那条、§6。
问题: HELP_TEXT(2473–2487)结构是【命令】六行 → 熬夜跨天说明 → 离线说明; 草案「HELP_TEXT + 一行」只能拼在最末, 与命令区隔两段。三处遗漏: 帮助行只写「回来」回日记, 没写「结束」也回(骨架③); §5.2 自己说撤回的跨文件边界「写进帮助不写进回执」, 但帮助行和 §6 都没有这句; 「记：xx」现有文案只举「晚安」, 没说切换关键词也能用它原样记。
改成: 新增 `helpText(rules, exitKeywords)`: rules 为空时原样返回 HELP_TEXT 常量(bindtest 与 `__internals.texts.HELP_TEXT`(5256)引用的是常量, 现有断言不动); 配了规则时在【命令】块「记：xx」那行之后插入「• 入梦/梦 → 切到「梦游太虚幻境」; 感悟 → 切到「玄学感悟」 (说「回来」或「结束」回日记; 想把这些词当内容记: 记：xx)」; 「撤回」那行改成「删掉最近记的最后一条(记在哪个文件夹就撤哪个)」; 「晚安 / 结束」那行不另起, 保持命令块短。

### A11. 切换/退出分支写 rest 必须走 `_writeEntry`, 否则语音原声丢
MEMO-8。涉及 §5.1 第 3 条、§7。
问题: 开了「保存语音原声」时, 原声只在 `_writeEntry → _writeVoiceEntry`(3845–3870)这条路上落库, `_pendingVoiceAudio` 在 `_dispatch` 开头(4104)挂上。语音「入梦。昨晚飞了」是谷雨记梦的主形态(醒来连发语音), 草案 §5.1 只说「把 rest 原样记进目标分区」, §7 只说「所有 writer.xxx 调用带上 folder」——实现者顺手调 `writer.write(rest, isVoice, day, folder)` 是最自然的写法, 那样转写文字进了梦境、原声静默丢, 回执照样「🎤 记下来啦~」, 违反 D12「记录意图的语音存原声」。代码视角认为这是实现假设不是草案缺陷, 但两位驳斥者都要求草案写明, 一句话的事。

## B. 需要谷雨拍板(产品选择题)

### B1. 每日提醒「只看默认日记」: 三个口径打架, 只在分区记的人天天被催
合并: MEMO-4 + MULTI-2 + ENG-1。涉及 §5.2 末尾 ⚠️ 审稿点、§1 骨架最后一句、§7 `_noteWrite`。
事实: 三处口径打架——`_noteWrite`(3839–3843)对任何写入清 `reminder_streak`, 草案说它「对所有分区一视同仁」; `_handle` FINALIZE 分支(4051)不分文件夹一律把 `reminded_date` 设成今天(分区里说「结束」就压掉提醒, 不说就催); 只有 `_reminderTick`(5006)的 `countDay()` 只读默认日记。结果: 朋友把工作全记在「工作」分区, 21:30 收到「今天还什么都没记呢」(对她是假话)→ streak=1 → 22:00 又在分区记一条 → streak 归 0 → 第二天再来一遍。D10 的「连续 3 天没写就闭嘴」永远达不到, 唯一出口是关掉提醒。D10 原话是「今天什么都没记才提醒, 记过就不打扰; 用户一回来(写任何东西)计数清零」。
「只看默认日记」字面在 §1, 但 HANDOFF 把它归在「边角(方向已聊, 细节待审稿轮)」, 草案也自标了审稿点, 所以只需要一句话确认: 这句是指「不做分区独立提醒」, 还是指「分区写入不算记过」?
- 选项 A(推荐): 任一文件夹今天有内容就不催。`countDay(dateStr, folder)` 加参数, `_reminderTick` 对 `_allFolders()` 逐个读, 遇 >0 提前 break; 现有「countToday=0 预判先跑」不动, 关着提醒/不到点时依旧零文件读取; 每天最多多读 N 个小文件一次。提醒文案不用改(这方案下它是真话)。三处口径统一为「写了东西 = 今天记了」, 与 D10 原话同一口径, 也不改 `_noteWrite` 语义。§1 那句在 D13 里改写为「不做分区独立提醒(§8 已有); 任一文件夹记过就不催」。
- 选项 B: 坚持只看默认日记。那必须同时改三处才自洽: `_noteWrite` 加 folder 参数, 只有默认日记写入才清 streak; FINALIZE 只在 `session.folder === ""` 或 signoff(晚安封全部)时设 `reminded_date`; 提醒文案「今天还什么都没记」改「今天日记还没记」。代价: 与 D10「写任何东西计数清零」矛盾, 且分区重度用户仍会被催 3 天才闭嘴。
推荐 A: 理由是 bot「说真话」是它被信任的根基, 且 A 改动更少。

### B2. 默认退出词「回来」在默认日记里也当命令, 会吞字; 默认词本身是日常用语
合并: MEMO-3 + MULTI-1 + ENG-10③。涉及 §1「退出词有内置默认(「回来」)」、§4 退出关键词说明、§5.1 第 3 条、§5.2「日记 | 退出词」行(且缺「日记 | 退出词 + 内容」行)、§6「退出(本来在日记)」。
事实: 实测现状 `detectIntent("回来。")` 与 `detectIntent("回来，吃了降压药")` 都是 DIARY, 整句照记。草案 §5.1 第 3 条「head 命中退出词 → 同上两种形态」不区分当前在不在分区, §5.2 把默认日记里的单独「回来」当命令(不落库, 回「本来就在日记里~」), 「日记 | 退出词 + 内容」这一格草案没写, 但按 §5.1 必然是剥掉「回来」只记 rest。所以只要配过一条规则(哪怕半年没用), 默认日记里: 语音转写「回来。」不落库(2.5 规定「入梦。」算单独一条); 「回来，吃了降压药」「回来，路上堵死了」(微信在停顿处加逗号)静默少字, 回执看不出, 翻库才发现。「回来」是备忘录人群的高频状态词(记爸妈几点回来、孩子放学回来), 与 D9 「可能是内容就不收」的词表标准冲突(光杆「睡了」「写完了」都因此不收); 它是内置默认不是用户自选, 吞字责任归产品。暴露面比看上去窄(head 精确比对, 「回来了」「爸妈回来」不命中), 但修法零成本。另: 草案 §1 把「回来」写成定案, HANDOFF §〇点五 原话是「候选「回来」」, 拍板的只是「有内置默认 + 可自定义」——草案要改回「候选」。
两个子问题:
问题 (a) 默认日记里退出词怎么处理:
- 选项 A(推荐): 退出词只在 `session.folder !== ""` 时参与匹配(`matchFolderSwitch` 多收一个 `currentFolder` 参数, 纯函数照样可测); 在默认日记里「回来」「回来，xx」整句照记, 与没配规则时完全一致。删掉 §5.2「日记 | 退出词」行和 §6「退出(本来在日记)」文案。把 §4 那句「没有分区可退, 「回来」照记为内容」扩展成「不在分区里时」。理由: 在日记里说退出词没有任何命令价值, 不必冒吞字风险; 想确认自己在哪已有「在吗」(骨架, 见 A8)且默认日记回执不带文件夹名本身就是信号。三位驳斥者中两位选 A。
- 选项 B: 保留单独一条的「本来就在日记里~ 想记什么直接发」确认(不落库, 回执可见, 想记就「记：回来」), 但「退出词 + 内容」在默认日记里整句原样落库、一个字不剥, §5.2 补一行「日记 | 退出词 + 内容 | 整句写入默认 | 记下来啦~ 今天第 N 段」。代价: 「回来。」(语音带句号)仍不落库。
任一选项都要 bindtest 加「有规则 + 在日记里发 回来，xx → 落库内容含「回来」」断言。
问题 (b) 默认词要不要换:
- 保留「回来」: 选了 (a)A 后风险只剩「在分区里说『回来，路上堵死了』会被踢回日记并写到默认」。
- 换「回日记」(3 个字, 语义与字段名「回到默认日记」一致, 语音说得清)或「退出」。
推荐换「回日记」: 与草案 §4 自己那句「关键词选日常说话用不到的词」一致, 且用户随时可改。不管选哪个, §4 退出关键词的说明加一句「同样选日常说话用不到的词」(直接改, 不用等拍板)。

### B3. 切错分区后说「撤回」, 撤掉的是上一条真内容而不是那次切换
MULTI-4(动作部分)。涉及 §2.4、§5.2「任意 | 撤回」行。
事实: 在日记里记了「今天开会很累」, 手滑发「感悟」(单独一条, 切到玄学感悟, 没写东西), 看回执切错了, 第一反应「撤回」——想撤的是这次切换。按草案撤回 = 撤 last_write 指向的最后一条 → 删了日记里「今天开会很累」, 人还留在「玄学感悟」, 重发落进玄学感悟, 一次手滑变三步补救。§2.4 属于可挑战范围; §5.2 只覆盖了「连说两次撤回」的边界, 没覆盖这个。D9 里撤回是唯一的救错口, 「撤销刚做的事」是它的自然语义。撤销切换不动文件, 不违反 D9 和契约规则 1。实现只需 session 加一个标记, 任何 `_noteWrite` 清掉它, 成本很低。
- 选项 A(推荐): 撤销切换。session 加 `switch_undo: {from: ""} | null`, 单独切换/单独退出时记来源文件夹, 任何成功写入置 null; UNDO 分支先看它——非空则 `session.folder = from`, 回「好的, 取消切换, 还在「{from 或 diaryFolder}」里」, 不动文件, 清标记; 再说「撤回」才走删内容(保住真想删上一条的人)。文档里点明一句: 「切换前文件夹」可能是另一个分区, 这是撤销不是 2.1 否掉的「退到指定文件夹」。理由: 与用户对「撤回」的心智一致, 一步回到原地。两位驳斥者选这个。
- 选项 B: 最简版。同样的标记, 但「撤回」不改 folder 也不删内容, 只回「刚才只是切换了文件夹, 没记东西; 想回日记说「回来」」并清标记。理由: 避免「撤回」一词两义。代价: 用户还要再发一条才回去。
- 选项 C: 不做, 靠回执预览自救。不推荐。

### B4. md5 复用跨分区插 wikilink, 与契约 v1.3「互不引用」自相矛盾
ENG-9。涉及 §5.5、§3 契约 v1.3 那句。
事实: `_findKnownMd5`(3990–4000)在全局 `ilink.fileMd5s` 里找, 命中就把那条的全路径交给 `appendLinkBlock`(3253)插 wikilink, 不区分根目录。草案 §3 给契约加的「每个根目录内部格式一致、互不引用」与 §5.5「跨分区引用也能打开, 可接受」在同一份文档里矛盾——契约是写给管库 Agent 的承诺, 不能写一句代码做不到的话。用户损害有限: 库内挪动文件夹 Obsidian 会自动改写 wikilink, 挪出库的话内容本身也不在了。ENG-9 原建议 A(按根隔离 md5、跨根重新下载)三位驳斥者一致否掉: 会把再发同一文件的用户推进 #193 解密坑、收到「改个名再发」, 比今天更差, 不能选。
- 选项 A(推荐): 跨根命中不下载、本地复制。`fileMd5s` 条目加 `root`; md5 命中但路径不在当前根 → `vault.readBinary(file)` 读本地那份, 走现有 `writeAttachment` 存进当前根的 attachments 并 `_rememberMd5` 新路径; 同根命中仍只插链接。`_findKnownMd5` 改为返回全部命中路径, 优先同根; 老条目没 root 的按默认日记算; fakeVault 桩补 readBinary。零网络、不触 #193, 契约「各根目录自包含, 附件不跨根引用」成立, 与「文件夹即管理」的需求一致。代价: 同一文件在两个根各占一份磁盘。
- 选项 B: 保留全局复用不动代码, 只把契约 v1.3 改成实话: 「可能有多个根目录, 每个根目录内部格式一致; 同一附件重复发送时可能被另一个根目录的笔记引用(wikilink 是库内全路径, 库内挪动文件夹 Obsidian 会自动更新链接)」; 复用回执顺手带来源: 「直接引用了「工作」里原来那份」。代价: 整体搬走一个分区目录(出库)就断链。
二者必居其一, 不能像现草案两边都写。
